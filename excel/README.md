# Excel front-end

`tes_toolkit.xlsm` is generated by `build_excel_toolkit.py`; the file tracked
here is a **placeholder** until someone runs the build on a machine with Excel.
It is the only binary artefact this repository tracks.

```bash
poetry run python excel/build_excel_toolkit.py --seed-cache
```

Build contract:

- The workbook contains **no business logic**. Every number comes from one of
  the three `xlwings` UDFs in `tes_pricer.interface.excel_bridge`:
  `TASA_CERO_CUPON`, `FORWARD_USDCOP`, `DV01_TES`.
- The UDFs never calibrate. They read `data/processed/latest_calibration.json`,
  written once by `python -m tes_pricer.interface.calibration_cache`, and cache
  it in memory by file modification time.
- `xlwings addin install` must have been run once on the workstation, and the
  functions imported once from the xlwings ribbon.
- The interpreter and `PYTHONPATH` live in the workbook's `xlwings.conf` sheet,
  so the file is portable across machines once those two cells are rewritten.
- UDFs run on Excel for Windows only; the build itself works on macOS too.

Step by step, including the manual Office configuration:
[docs/excel_setup_guide.md](../docs/excel_setup_guide.md).
